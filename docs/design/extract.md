# Extract: design

How `dolly extract` turns one real repository into a pattern, deterministically.
Decisions here were reviewed adversarially before implementation (2026-07-24);
the contract-level rules live in [ADR-0003](../adr/0003-deterministic-extraction.md).

## Ground rules

1. **Pure function of the working tree.** Same repo bytes + same dolly version →
   byte-identical `pattern.md` on any OS. No git history, no clock, no network,
   no locale-dependent behavior. dolly walks the tree itself rather than asking
   `git ls-files`, so a tarball and a clone extract identically. The one
   carved exception is [ADR-0005](../adr/0005-history-facets.md): `commits`
   and `releases.versioning` read the log and the tags, bounded and silent
   without them, and are the only fields a clone and its tarball can differ in.
2. **Confidence is rules, not scores.** No stored floats. Each scanner has
   explicit evidence classes, and a finding either clears the bar or it doesn't.
3. **Three-way degradation.** Every candidate finding becomes exactly one of:
   a **facet** (high evidence, machine-enforceable), a **counted prose note**
   ("4 of 6 directories under src/ contain routes.ts; add `src/{name}/routes.ts`
   to layout if intentional"), or **silence** (incidental content). A wrong facet
   is structurally impossible below the bar; a stale curated list costs coverage,
   never correctness.

## Architecture

```
inventory (one shared walk)
   ├── layout scanner
   ├── naming scanner
   ├── toolchain scanner
   ├── dependencies scanner
   └── languages scanner
        ↓
   orchestrator: merges facets, renders one "## Extraction notes" prose
                  section (### subsections in fixed facet order), returns
                  the pattern document plus captured config files
```

Each scanner is a pure function `(inventory, root) → { facet?, notes[] }`.
The orchestrator owns all prose rendering so scanners can't disagree on headings.

## The shared inventory

One walk feeds every scanner, so all facets in one pattern rest on the same
evidence. It applies, in order:

- `.gitignore` semantics (the `ignore` package, per-directory, `!` negation).
- A built-in deny list: build output (`dist`, `build`, `out`, `coverage`,
  `.next`, `target` when a manifest implies it…), caches, virtualenvs,
  `node_modules`, lockfiles by name.
- Vendored dirs (`vendor/`, `third_party/`): recorded as a single directory,
  never descended into.
- A generated-code sniff on the first 1 KiB of files
  (`@generated`, `code generated by`, `do not edit`); generated files are
  invisible to *all* scanners, so committed protobuf output can't flip a vote.
- Symlinks skipped entirely (consistent with the M1 bundle policy).
- Paths POSIX-slashed, NFC-normalized, sorted segment-wise by code point.
  Enumeration order can never leak into output.

## Scanners

### Layout

Three evidence classes decide structural vs incidental:

- **E1 external prior**: root anchor files (README*, manifests, LICENSE*,
  tool configs…) and directories within the depth cap.
- **E2 self-declaration**, where the repo asserts structure: workspace globs
  (package.json workspaces, pnpm-workspace.yaml, Cargo `[workspace].members`),
  `.gitkeep` (evidence for its directory only; the placeholder itself is
  never a listed file or a shared shape, so a scaffold's empty directories
  cannot vote their placeholders back into the pattern). Workspace members
  form a group even with nothing inside them yet.
- **E3 sibling-shape voting**: if ≥3 sibling dirs share ≥2 internal paths at
  ≥60% support (with the child's own name normalized to `{name}`),
  they generalize to `parent/{name}/` plus the shared core. The same vote runs
  over **file** siblings, so `routers/users.py|items.py|orders.py` becomes
  `routers/{name}.py`. A stoplist (src, tests, utils, components…) separates
  open-set instance names from structural vocabulary. A core path carrying
  the source project's own name (a versioned docs page about it) is content,
  never structure another project could share, and is dropped from the vote.

Files are incidental by default: only anchors, toolchain-claimed configs, and
template cores are listed. That rule, not the entry budget (50), is the primary
size bound. A group's core is budgeted too (2026-09-11): the eight best
supported paths are listed and the rest become one counted note, since a
module shape whose members share dozens of files (every sample's docs pages)
would otherwise push the whole layout past the budget with entries the
budget never drops, being required. `required: true` demands corroboration: a known root-vocabulary
name, workspace evidence, `.gitkeep`, or unanimous template support; one
example repo alone never justifies requiring a path. Near-miss groups degrade
to counted prose notes with a paste-ready path.

`{name}` semantics (documented in the schema): a placeholder for exactly one
path segment. In check it matches any single segment (case violations are the
naming facet's own finding); in new, root-level `{name}` expands to the project
name and module-level template entries are skipped.

### Naming

Majority vote over filename stems (text before the first dot) against five
case-style regexes. A name votes only if it matches **exactly one** style
(`Button` → PascalCase; `utils` matches three and abstains; `Foo-Bar` matches
none and counts as dissent). No word segmentation needed at extract time.
Excluded from voting: dotfiles, ecosystem-mandated names (README, Dockerfile,
index.*, __init__.py, lockfiles…), framework route segments (`[id].tsx`,
`+page.svelte`), and everything under `.github/` (wizard vocabulary). Trailing
`_test`/`_spec` is stripped so Go/pytest idioms don't cast forced snake votes.
Directories add the closed structural vocabulary (`src`, `tests`, `lib`,
`docs`, the layout stoplist): those names carry the ecosystem's case, so they
neither vote nor are judged, and a PSR-4 tree with PascalCase namespaces under
a lowercase `src/` still votes PascalCase directories.

Scopes: one global pool, one per-extension bucket, one directories pool.
A pool emits a facet iff winner ≥ 80% of (votes + dissent) and sample ≥ 5,
in integer math. Per-extension overrides beat per-directory rules because
extension correlates with artifact kind and generalizes to unseen directories.
Mixed pools with sample ≥ 5 degrade to a prose bullet carrying the full
distribution.

### Toolchain

A data-driven matrix of rows `(tool, roles, fingerprints, capture spec)` per
ecosystem (js, python, rust, go, and since 2026-09-01 ruby, the jvm through
maven or gradle, php, and .net, detected from root manifests, or from the
project files a .net solution spreads over directories). Fingerprints
are dedicated config files, manifest sections, and lockfiles, tested in the
tool's own resolution order. Roles: packageManager, formatter, linter,
typechecker, testRunner, taskRunner, ci (exclusive: PM, formatter, testRunner;
additive: the rest).

Conflicts on exclusive roles run a deterministic ladder: drop candidates whose
parsed config disables the role → unique reference in manifest scripts wins →
unique devDependency declaration wins → otherwise **no facet** plus a conflict
note naming all candidates. A configless test runner (vitest with zero config)
still qualifies when it is both script-invoked and dev-declared.

Captured configs are **real files** under the pattern's `toolchain/` directory:
diffable, hand-editable, carried by `.dolly` bundles for free. The facet's
`configs` record maps `sourceId` (repo path or `manifest#dotted.path`) to the
pattern-relative file. Embedded subtrees (pyproject `[tool.ruff]`, tsconfig
`compilerOptions`) are re-serialized canonically. Capture gates: no symlinks,
≤ 256 KiB, no machine-specific home paths, never credential files (.npmrc…).
Check binding modes (verbatim vs subset) are an M4 decision; the file layout
already supports them.

The matrix is seeded with the per-ecosystem head (~the top tools you'd
actually meet) and grows from evidence; a missing row degrades to a prose
note, never a wrong facet.

### Dependencies

Manifests parsed: package.json (+ workspaces), pyproject.toml
([project] / PEP 735 groups / poetry fallback), requirements files (only when
pyproject declares no dependencies; shadowing is noted), Cargo.toml
(workspace-aware), go.mod (minus `// indirect`), and since 2026-09-01 the
Gemfile (`gem` lines with their groups; a gemspec is code and stays unread),
pom.xml (`<dependency>` blocks, test and provided scopes as dev) or a
Gradle build file (`implementation("group:artifact:version")` and its
kin), composer.json (require and require-dev, the platform entries
skipped), and every .csproj in the tree (`<PackageReference>`, a test
project's as dev, central versions from Directory.Packages.props). Internal workspace packages
and path/git specifiers are excluded from facets.

Purpose classification (`http-client: httpx`) uses a small curated in-core
registry that doubles as a **generalization filter**: only registry-known,
conflict-free, external, direct deps become facets, so an app's business deps
never scaffold into unrelated projects. Tool purposes (lint, format, test,
typecheck) are **owned by the toolchain facet**: the registry defers to its
resolution so the two facets can never contradict. Test-family purposes are
forced into the dev bucket even where the manifest has no dev section (go).
Unknown deps are listed alphabetically in prose.

`versionPolicy` comes from a per-dep modal vote over ecosystem-aware specifier
shapes (Cargo bare `"1.2.3"` is caret; Go abstains, as authors have no shape
choice), emitted only at ≥ 3 votes with a ≥ 2/3 supermajority.

Polyglot repos: the primary ecosystem (the language-derived one toolchain
uses, falling back to the most classified deps when it has none) gets the facets;
each secondary ecosystem gets one prose note listing its purposes, ready for
hand-promotion (the open record accepts keys like `npm/test` if wanted).

### Languages

Programming: a lookup pipeline (exact filename map, longest-extension map,
shebang map) over linguist's data, generated at build time into a committed
`languages-data.json` (reviewable diffs, zero runtime dependency). Component
formats linguist types as "markup" (Vue, Svelte, Astro…) count as programming
for facet membership. Data formats (YAML, JSON) are recognized but excluded
from shares. Ambiguous extensions (.h) resolve by voting with unambiguous
sibling bytes, falling back to a fixed default table. The facet is an
**ordered sanctioned list** (dominant first); percentages are unenforceable
and live in a prose note. Membership: ≥ 2 files and ≥ 1% share, or ≥ 5 files.

`languages.versions` records runtime pins from `.nvmrc`, package.json
`engines`, `requires-python`, Cargo `rust-version`, `.python-version`.

Natural language: tinyld (pure JS, deterministic) over a cleaned docs corpus
(README + docs/, code/URLs/badges stripped) in 512-char chunks with majority
vote. Facet only when the corpus is long enough (≥ 512 chars) and chunk
agreement ≥ 0.8; bilingual docs degrade to a note; primary BCP-47 subtag only.
Comment sampling was considered and rejected for v1 (large machinery, little
signal).

### Commands (M3)

The toolchain facet's resolved `taskRunner` decides the single source: reading
any other file could contradict it. From package.json scripts: canonical verbs
only (build, check, clean, dev, docs, format, lint, start, test, typecheck,
plus the fmt/type-check aliases), and a body that calls a non-captured script
(`npm run knip`) degrades to a note, because it could not run in a fresh
project. From a justfile/Makefile: only self-contained recipes (no parameters,
no dependencies, one body line; just's quiet `@recipe` prefix allowed);
anything else cannot be replayed into a scaffolded taskfile without guessing.
A body that reads a taskfile variable (just's `{{bin}}`, make's `$(BIN)`)
degrades the same way: those are defined in the file's header, which no
scaffold reproduces. Canonical spellings own their verb; an alias only ever
fills a gap, so recipe order in the file cannot change the facet.

### Scaffold (M3)

Templates are captured from the `{name}` groups the layout scanner already
voted into existence, so both facets rest on the same members. The evidence is
**agreement**: every member must carry the file, and the files must be
byte-identical once each member's own name is replaced by `{{name}}` (whole
word only, so capturing `cli` never rewrites "client") and the package scope by
`{{project}}`. One dissenting member means the file is content, not convention:
a counted note with the largest agreeing group's size. Gates mirror the
toolchain's: ≤ 64 KiB, text only, no machine paths, and nothing that already
writes `{{ }}` (Vue, Handlebars, Jinja), because dolly's own placeholder must
be unambiguous on instantiation. Only the scope form of the project token is
rewritten: a bare token like "test" appears in ordinary code, and mangling it
would be worse than leaving it.

Agreement alone is not safety, though: whatever is *constant across siblings*
survives the byte-identical test by construction, and a project's identity is
exactly the kind of thing that is constant (an author's email, a repository
URL, a homepage). So a final identity gate refuses any capture whose
normalized text, or whose target path, still carries an email address or the
source project's own name; refusing costs a counted note, while capturing
would ship someone else's identity inside a shared `.dolly` bundle. The name
is read once per repository (`extract/identity.ts`) from whichever manifest
the ecosystem has: the npm scope, Cargo.toml, pyproject.toml, go.mod, a
gemspec, pom.xml, the Gradle settings, composer.json, a solution or project
file. Templates live at `templates/<target path>`
inside the pattern, a mirror of the project tree, hand-editable, carried by
`.dolly` bundles for free.

### License (M3)

Manifest fields first (package.json `license`, pyproject `[project].license`,
Cargo `[package].license`), checked against a short list of ids dolly actually
knows rather than a permissive shape: a field reading "Proprietary" or
"Copyright Acme" is a note, not a facet, and the hand-editable schema still
accepts the whole SPDX grammar. The LICENSE file's text is the fallback,
fingerprinted against the handful of texts that dominate open source.
Disagreement (between manifests, or manifest vs text) yields a note and no
facet. The GPL family always degrades to a note (its text cannot say "-only"
vs "-or-later"). Two permissive pairs differ only by their notice-retention
clause, so the fingerprint demands that clause explicitly: without it 0BSD
would read as ISC, and MIT-0 as MIT.

### Commits and releases (M8)

The history facets, under ADR-0005's exception and detailed in
[exports.md](exports.md). `commits` votes over the last 200 non-merge
subject lines from `HEAD`: a style (Conventional Commits, gitmoji) at 80%
of a sample of at least 10, the conventional types seen at least twice,
whether scopes are required, optional, or never used, and the case of the
subject's first letter; a style between half and the bar is a counted
note, and a free style is emitted only when the case vote says something.
`releases.versioning` votes the tag shape (semver, or calver when the
tags are year-led) at 80% of at least 3 tags; `releases.changelog` and
`releases.tool` are tree evidence: a `CHANGELOG.md` that cites Keep a
Changelog or uses its headings, and a release tool's root fingerprint
(`.changeset/`, `.releaserc*`, `cliff.toml`, and the rest of the small
table in `extract/releases.ts`). A changelog in a style dolly does not
recognize is a note.

## Several repositories (2026-09-01)

`dolly extract a b c --name style` extracts each repository on its own,
exactly as above, then keeps what they agree on (`extract/agreement.ts`).
The rule is ADR-0003's three-way degradation applied across trees: a
facet value becomes the pattern's when a majority of the repositories
carry it and every one that does says the same thing; a value carried by
a minority, or one the carriers disagree on, is left out and named in an
"Agreement" note ("naming.files disagrees: a says kebab-case, c says
snake_case; left out"), so the author can settle it by hand. Records
(commands, versions, dependencies by purpose, naming overrides) agree key
by key; lists (the sanctioned languages, the commit types) keep the
members a majority carries, dominant first, and the sanctioned languages
need the repositories to agree on the dominant one first (two repositories
that share only Shell do not write Shell); layout keeps the entries a
majority carries, required only when every carrier says so, and names
the minority's paths in one note. A captured config agrees byte for byte
or, when it is JSON or TOML, keeps only the keys every copy shares,
reserialized in the formatter's shape, which is exactly what subset
binding then enforces; a template must match byte for byte. Each
repository's own notes follow the agreement notes under its name. The
order the repositories were given breaks ties, and the whole is still a
pure function of the trees. The daemon takes `dirs` on `POST
/api/extract` for the same thing.

## Schema changes (one consolidated diff, format stays 1)

- `naming.extensions`: per-extension case overrides; `files` is the default
  for unlisted extensions.
- `languages.programming`: record → ordered `string[]` (sanctioned languages,
  dominant first). Semantic roles ("backend: python") are not inferable from
  one repo and wait for the AI layer.
- `languages.versions`: `record<runtime, range>`.
- `toolchain.typechecker` / `testRunner` / `taskRunner` / `ci`: optional
  strings beside formatter/linter.
- `toolchain.configs`: semantics change to `{sourceId: patternRelativePath}`
  with bytes as real files under `toolchain/`; values validated to stay inside
  the pattern directory.
- `layout[].path`: refined to relative, POSIX slashes, no `..`/empty
  segments; directories end with `/`.

## Deferred facets (added at the milestone that consumes them)

| Facet | Milestone | Shape sketch |
|---|---|---|
| `testing`: placement + file pattern | landed at M4 (check enforces it) | `{ placement: colocated, filePattern: "{stem}.test.ts" }` |
| `toolchain.hooks`: hook manager | landed at M4 | `hooks: lefthook` |
| env hygiene (".env must be gitignored") | landed at M4, built-in check (no schema) | n/a |
| `commits`: message grammar | landed at M8 under ADR-0005 | `{ style: conventional, types: [...], scope: optional, subject: lower }` |
| `releases`: versioning/changelog/automation | landed at M8 | `{ versioning: semver, changelog: keep-a-changelog, tool: changesets }` |
| `naming.branches` | deferred: branch names are local refs, not shared history, so one clone is not evidence of a convention | `"{type}/{topic}"` |

Rejected outright: `env.variables` (app contract, not maintainer DNA),
import-boundary facets (would rebuild dependency-cruiser inside the engine;
layering rules live in prose, which exports and the AI layer consume), README
section/docstring facets (one repo's headings are content, not convention;
the extractor writes them as prose observations instead).

## Taste constants

All tunables live in one exported const per scanner so behavior changes are
visible diffs. Current values (naming 80% / sample ≥ 5; layout MIN_GROUP 3,
support 60%, depth cap 4, entry budget 50, 8 core paths per {name} group;
toolchain capture cap 256 KiB;
languages 1% share, natural-language 512 chars / 0.8 agreement; dependencies
2/3 supermajority; testing 80% / sample ≥ 2; commits 80% / sample ≥ 10 over
the last 200, note at 50%, a type at 2 sightings; releases 80% / tags ≥ 3)
are to be ratified against the three M2 acceptance repos.
